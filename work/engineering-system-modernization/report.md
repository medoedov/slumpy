## Что пока не доказано

Автоматический запуск нового hook требует штатного доверия к определению через `/hooks` и
проверки в свежем локальном клиенте. Версия CLI и поддержка hooks проверены; поверхность Desktop
и её способ оркестрации не приравниваются к CLI. Глобальные пользовательские настройки не менялись.

Не выполнены живые сравнительные прогоны Codex/Claude, проверка POSIX-ветки завершения процессов
и исторического сетевого варианта eval. Bash-обёртка проверена с локальным stub: ошибка 7 дошла до
вызывающего процесса; модель не запускалась. Swift/Xcode на этом Windows-хосте
отсутствуют; сборка, симулятор, устройство, UI и расход ресурсов приложения не проверены.
Переносимая fixture не доказывает качество Swift-кода или преимущество одной модели.

Сценарии продолжения и условия честного сравнения сохранены в `evals/engineering/protocol.md`.
Остаются прежние ограничения бюджета и запрет критических регрессий; качество и стоимость
новых формулировок пока не измерены. Исследование источников и отклонённые кандидаты — в audit.md.

## Как работать дальше и откатить

Вы задаёте продуктовую цель. Агент восстанавливает решения, фиксирует исходное состояние,
сам исследует технические вопросы, реализует задачу и запускает проверку на итоговом состоянии.
Отчёт разделяет проверенное, недоступное и незавершённое. При переключении клиента продолжается
тот же план с общими исходниками; решения и интервью не начинаются заново.

Команда проверки — `python scripts/check`. Для проверки всей задачи агент задаёт
`SLUMPY_CHECK_BASE` равным commit начала задачи; после изменения `scripts/` также запускает
`python scripts/test-checks` и `python scripts/test-checks --mutants`. Успешная проверка документов
сама по себе не означает готовность приложения.

Изменения оставлены локально для просмотра. Исходное отслеживаемое состояние — commit
`d4d87c32c75fb70834a4e582b880a067440044d6`; первоначально рабочее дерево было чистым. Откат
затрагивает только перечисленные в Git diff файлы и добавленные артефакты этой задачи. Отключённые
опасные Git hooks следует оставить отключёнными. Остановленные осиротевшие проверки не содержали
пользовательских данных; при необходимости проверочный прогон запускается заново.
