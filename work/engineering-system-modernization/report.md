# Результат модернизации

Локальные изменения подготовлены; основная реализация прошла независимое ревью. Последующие
исправления проверены напрямую, их границы перечислены ниже.

## Что сохранено и исправлено

Сохранены общий AGENTS.md, канонические материалы в `.claude/`, три адаптера Codex, один reviewer,
ADR и продуктовые решения, краткий brief для T1 и ограничение числа ревью. Продуктовый объём
Slumpy не изменён. Публикации, push, установки и платные модельные прогоны не выполнялись.

- Упаковщик `evals/scripts/build_plugin.py` создаёт только новый каталог в разрешённой области;
  существующие каталоги не удаляет. Манифест хеширует фактическое содержимое, включая
  незакоммиченные изменения. Сборщик результатов также больше не удаляет каталоги по tracePath.
  Ошибка запуска eval больше не теряется в итоговом коде выхода.
- `scripts/check-risk` принимает исходный commit задачи: уже закоммиченные изменения на `dev`
  больше не исчезают из проверки при явно заданной базе.
- `scripts/check` обслуживает Claude и Codex через отдельные форматы ответа. Подготовлен
  `.codex/hooks.json`; ограничены повторное продолжение и время выполнения. Невозможность
  проверки не превращается в подтверждение готовности.
- `scripts/test-checks` завершает дочерние процессы при таймауте. Обнаружены и после повторной
  проверки остановлены ровно 30 старых осиротевших проверок из удалённых временных каталогов.
- В локальной настройке Git отключены старые hooks: вопреки документации они оставались
  подключёнными и могли запустить запрещённый конвертер. Сами `.githooks/` не изменены.
- Общий процесс явно возлагает техническую полноту на агента; передача работы сохраняет цель,
  причины решений и проверенное состояние. Ревью учитывает последствия исправлений для
  вызывающего кода и препятствия безопасной работе изменяемого сценария.

## Что доказано

Польза исправлений инструментов подтверждается конкретными отказами до исправления и
проверками после него, а не длиной инструкций. Полный список — в plan.md и script-verification.md.

- Проверки документов проходят и явно сообщают, что сборка приложения, его тесты и lint пока
  не подключены. Финальный self-test: **266 случаев прошли**. Полный мутационный прогон за
  81 минуту 53,5 секунды обнаружил 892 из 895 вариантов и вернул ошибку. Разбор выявил один
  эквивалент и два пробела в тестах; новые тесты обнаружили оба оставшихся изменения.
  Повторный полный прогон обновлённого набора из 894 вариантов не выполнялся.
- Упаковщик: **6 проверок прошли, 1 пропущена** из-за отсутствия прав Windows на создание
  symlink. Реальная проверка junction прошла; старые версии Python отклоняются до файловых операций.
- Исполняемая задача хранения и последующего изменения: **10 тестов эталона прошли**;
  намеренно ошибочная реализация проваливает четыре метода. Проверяются сохранение данных,
  авария и повтор, совместимость с исходным хранилищем, конфликтующие запросы и неверные типы.
- Независимое ревью: первый раунд обнаружил два класса дефектов; после исправлений второй
  завершился без замечаний. Ревьюер не изменял файлы. Позже найденное удаление в сборщике результатов
  исправлено и подтверждено отдельным регрессионным тестом без третьего раунда. Последующие
  исправления подготовки мутационных тестов, классификация эквивалентов и уточнения текста
  также не покрываются вторым ревью; их проверка записана отдельно.
- Windows-команда Codex hook проверена из подкаталога: нашла корень и вернула корректный JSON.
  Это не подтверждение автоматического события Stop в клиенте.

Время отдельных проверок приведено в протоколах. Надёжная суммарная телеметрия токенов и
сопоставимая стоимость моделей недоступны; проценты подписочной квоты в токены не переводились.
Хеши итоговых файлов, HEAD, база задачи и локальная настройка hooks сохранены в
`verification-state.json`; артефакт исключает самого себя и игнорируемые временные результаты.

## Что пока не доказано

Автоматический запуск нового hook требует штатного доверия к определению через `/hooks` и
проверки в свежем локальном клиенте. Версия CLI и поддержка hooks проверены; поверхность Desktop
и её способ оркестрации не приравниваются к CLI. Глобальные пользовательские настройки не менялись.

Не выполнены живые сравнительные прогоны Codex/Claude, проверка POSIX-ветки завершения процессов
и исторического сетевого варианта eval. Bash-обёртка проверена с локальным stub: ошибка 7 дошла до
вызывающего процесса; модель не запускалась. Swift/Xcode на этом Windows-хосте
отсутствуют; сборка, симулятор, устройство, UI и расход ресурсов приложения не проверены.
Переносимая fixture не доказывает качество Swift-кода или преимущество одной модели.

Сценарии продолжения и условия честного сравнения сохранены в `evals/engineering/protocol.md`.
Остаются прежние ограничения бюджета и запрет критических регрессий; качество и стоимость
новых формулировок пока не измерены. Исследование источников и отклонённые кандидаты — в audit.md.

## Как работать дальше и откатить

Вы задаёте продуктовую цель. Агент восстанавливает решения, фиксирует исходное состояние,
сам исследует технические вопросы, реализует задачу и запускает проверку на итоговом состоянии.
Отчёт разделяет проверенное, недоступное и незавершённое. При переключении клиента продолжается
тот же план с общими исходниками; решения и интервью не начинаются заново.

Команда проверки — `python scripts/check`. Для проверки всей задачи агент задаёт
`SLUMPY_CHECK_BASE` равным commit начала задачи; после изменения `scripts/` также запускает
`python scripts/test-checks` и `python scripts/test-checks --mutants`. Успешная проверка документов
сама по себе не означает готовность приложения.

Изменения оставлены локально для просмотра. Исходное отслеживаемое состояние — commit
`d4d87c32c75fb70834a4e582b880a067440044d6`; первоначально рабочее дерево было чистым. Откат
затрагивает только перечисленные в Git diff файлы и добавленные артефакты этой задачи. Отключённые
опасные Git hooks следует оставить отключёнными. Остановленные осиротевшие проверки не содержали
пользовательских данных; при необходимости проверочный прогон запускается заново.
