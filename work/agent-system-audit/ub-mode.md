# Что взято из ub-mode Роберта Мартина

> **Дата:** 2026-10-27. **Источник:** [unclebob/ub-mode](https://github.com/unclebob/ub-mode), первый коммит 2026-10-25. Это сокращённые правила poteto из плагина [pstack](https://github.com/cursor/plugins/tree/main/pstack) (MIT) и четыре инструмента автора: crapper, dryer, mutator, uml-viewer.

## Главный вывод

По постам автора в X за 2026 год он перестал читать код агентов. Вместо этого он опирается на автоматические проверки: тесты, метрики, мутационное тестирование. Длинные правила агенты теряют, а медленные необязательные проверки пропускают. Посты агент видел в выдаче поиска, сами страницы были закрыты. У нас код не читает никто, поэтому автоматические проверки для нас важнее, чем для автора. План проверок записан в Project Knowledge: `patterns.md`, раздел Verification.

## Поправки к первому варианту

Предложенный сначала вариант в шести местах сделал бы хуже:

1. Строка проверки «в конце коммита» конфликтовала со строками об авторстве, которые сессия ставит последними. Теперь требуется только наличие строки.
2. «Один писатель на общее состояние» буквально не выполним: монитор DeviceActivity работает при закрытом приложении и сам записывает конец сессии. Теперь сначала у каждого писателя своё место, а упорядочивание нужно только при одном общем месте.
3. Требование заводить отдельный слой моделей для проверки недопустимых состояний противоречило правилу «новый слой только с причиной». Оставлен только вопрос в меню.
4. «Заглушка вместо падения не исправление» могло оставить падение у пользователя. Теперь защитная проверка может остаться, но исправлением считается устранение причины.
5. Требование «убить всех выживших мутантов» толкало бы к тестам, привязанным к внутренностям кода. Теперь: нет новых выживших на изменённых строках, без целевого процента.
6. Критерий теста переехал из ревьюера в правила Swift. У ревьюера осталась ссылка, чтобы проверка не выпала.

## Что не взято и почему

- **Инструменты автора** (crapper, dryer, mutator): Swift не поддерживают, проверено по исходникам. uml-viewer: направление зависимостей у нас проверяет компилятор через пакет логики; лицензии нет.
- **Обязательный тест перед каждым изменением.** В исходном pstack тест пишется, когда есть дешёвый честный путь. В облачной сессии тесты не запускаются. Обязательный тест для бага у нас уже есть.
- **«Устранять дублирование от 0.8».** Ведёт к неверным абстракциям. Принцип ревьюера: дублирование дешевле неверной абстракции.
- **«Вычитай, прежде чем добавлять» и «перепроектируй с нуля» как обязанность.** Противоречат правилу Scope, расширяют изменения. Полезная часть есть в вердикте ревью `rethink approach`.
- **Build the Lever.** Частично есть в правиле «повторяющийся класс ошибок чинить инструментом» (CLAUDE.md, Review and lessons); сбоя, который правило предотвратило бы сверх этого, не видно.
- **Outcome-Oriented Execution.** Касается многошаговых переделок с запланированной поломкой посередине; таких задач пока нет.
- **Журнал каждого действия для владельца.** Владельцу нужен отчёт о решениях; журнал шагов уже ведётся в `plan.md`.
- **Пуш в main в конце работы и очистка рабочих копий.** Пуш в main решает владелец; рабочих копий у нас нет.
